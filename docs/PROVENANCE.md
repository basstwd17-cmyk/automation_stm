# 원본과 배포 변경점

2026년 11월 10일 로컬 PCB 프로젝트의 펌웨어와 측정 도구를 모았다. 원본 기준 Git 커밋은 `255cec64`이며 줄끝을 LF로 정규화한 파일별 SHA-256은 [source_manifest.json](source_manifest.json)에 기록한다.

→ 개발보드의 조이스틱 예제와 PCB용 외부 입력 펌웨어를 별도 저장소로 관리한다.

## 보관한 상태

- EEV3=Rising/동기식, EEV5=Level/Fast, Timer D 기준 96 tick·펄스 폭 109 tick.
- 기본 헤더는 `k15/config_input_reference.json`과 일치하는 연속 입력 4단계 계획.
- A/B·K15·K37의 설정·실행기·복구 도구와 기존 결과 분석 코드.
- ST HAL·CMSIS·USB 드라이버와 기존 라이선스 파일.

## 배포 조정

1. 연속 입력의 개수 기반 전환을 유지하고, guard 필드가 없는 버스트 계획은 300 ms 유휴 구간 전환을 복원했다.
2. `prepare_plan.py`로 설정에 맞는 헤더를 장비 없이 생성한다.
3. CubeIDE·CubeProgrammer 환경 변수와 최초 IDE 빌드 안내를 추가했다.
4. PC 절대 결과 경로를 상대 경로로 바꾸고 K37 렌더러에 결과 폴더 인자를 추가했다.
5. 전용 K15 CSV 재분석 도구와 연속 입력 계획의 잘못된 generic runner 사용을 차단하는 검사를 추가했다.
6. Python 의존성을 정리하고 `common/` 이전 중복 파일을 제거했다. 기존 UI·runner 진입점은 유지했다.

→ 코드 통합을 위한 호환 조정이며, 새 DFU 업로드나 장비 실험으로 성능을 재측정한 결과는 아니다.

## 과거 결과와 현재 코드

측정 폴더마다 당시 펌웨어 전체와 이벤트 레지스터가 모두 저장되어 있지는 않다. 과거 페이지의 결과를 이 배포 커밋에서 새로 얻은 값으로 표시하지 않는다.

→ 재측정 시 코드 커밋·헤더·config·이벤트 모드·배선·원시 데이터를 함께 기록한다. `.ioc`만으로 실행 펌웨어를 판정하지 않는다.
